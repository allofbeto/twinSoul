# twinSoul

This is just a twin soul campaign tool

# Frontend Commands:
npm start
    Starts the development server.

npm run build
    Bundles the app into static files for production.

npm test
    Starts the test runner.

npm run eject
    Removes this tool and copies build dependencies, configuration files
    and scripts into the app directory. If you do this, you can’t go back!

# Backend Commands:

## Create Models:
- rails g [ModelName]
- then add the needed cols in the migration file
- then db:migrate
- then add any required has_many or belongs_to in the associated models
- then Move on to create a controller

## Create COntrollers:
- rails g controller api/v1/[model_name_controller{make_plural_mannually}]
- then add it to the routes.rb file
- then add the associated backendhelpers in the backendHelpers.ts file 
## Deploying

The site and the API deploy separately.

**Website (Cloudflare Workers).** `wrangler.jsonc` serves the built React app (`frontend/build`); the build runs from the root `postinstall`/`build` scripts. In the Cloudflare project's *Build variables* set, **before building** (they're baked into the site):

| Variable | Example |
| --- | --- |
| `REACT_APP_API_URL` | `https://twinsoul-api.onrender.com/api/v1` |
| `REACT_APP_CABLE_URL` | `wss://twinsoul-api.onrender.com/cable` |

**API (Render).** `render.yaml` is a Blueprint for the Rails app plus a Postgres database: Render dashboard → *New +* → *Blueprint* → pick this repo. On first start it creates the schema and seeds the SRD data (`backend/bin/render-start.sh`). Environment:

| Variable | Notes |
| --- | --- |
| `CORS_ORIGINS` | Your website's address, no trailing slash. Comma-separate several. Already set in `render.yaml`. |
| `SECRET_KEY_BASE` | Generated by Render. |
| `DATABASE_URL` | Wired from the Render database. |
| `REDIS_URL` | Optional. Without it, live theatre connections use an in-process adapter, which is fine for a single instance. |

Check the API with `GET /healthz`, and CORS with:

```
curl -i -X OPTIONS https://YOUR-API/api/v1/auth/register \
  -H "Origin: https://YOUR-SITE" -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type"
```
You should see `access-control-allow-origin: https://YOUR-SITE`.
